# Validation and fault injection

The [contributor matrix](../CONTRIBUTING.md#required-local-validation) defines local checks. Native process tests are specific to their OS implementation; record assertion-level skips with reasons. Windows verification does not establish Linux or macOS acceptance. CI runs all three operating systems with Node 24. The local demo verifies a real script dispatch, report ingestion, manual merge/approval and HTTP console representation without a model account.

`pnpm test:ablation` measures whether selected regression tests detect known faults. It copies release sources into a disposable directory under `.alba/ablation`, links installed dependencies, verifies each selected suite against an unmodified copy, then changes exactly one source expression at a time. Each mutation runs its related tests once, with a timeout and captured output. Source restoration happens between mutations; temporary repositories and workers are confined to the disposable directory. The copy is removed in `finally`.

The script covers report parsing, dispatch eligibility, review merge checks, worktree cleanup, service locks, process-tree membership, library format validation and the demo worker protocol. It prints caught, survived or infrastructure-error for each fault and writes a small sanitized [result report](ablation-results.md). A baseline failure, mutation mismatch or timeout is an infrastructure error, not a caught fault. A surviving fault is reported and makes the command fail; add coverage or explicitly document the gap. Run it before removing or merging tests. It is optional in CI because subprocess and native cleanup tests are slow.

`pnpm check:docs` checks local Markdown links, images, reference links and heading fragments without contacting external sites. `pnpm check:release` scans Git-tracked files and unignored new files (`git ls-files --cached --others --exclude-standard`) for obsolete identifiers, untranslated Chinese, BOM, private absolute paths/usernames, internal tickets and credential-shaped literals. Ignored dependencies, private state, generated builds and .pnpm-store are outside that source scan; tracked files remain in scope even in ignored folders. Invalid UTF-8 text is reported with its filename. Review distributable bundles separately. `pnpm check:changelog` checks the package version entry. The release scanner is a guard, not a secret-management boundary.
